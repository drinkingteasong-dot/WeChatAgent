新版测试覆盖鉴权、超时、无模型列表、模型误填网址、模板缺少音频、转换组件缺失、SILK 测试不确定状态、缓存与并发保存、密钥脱敏以及禁用插件的宿主检测。开发版 94 项相关回归通过，公开版 61 项相关回归及独立语音宿主链路用例通过。模拟界面已核对模型自动选择、成功状态保存与误填后的状态失效；未验证用户真实 API。

## 已修复的问题

| 问题 | 修复 |
| --- | --- |
| 安装器、DSH、worker 和界面分别维护权限与能力列表 | 统一读取 `packages/plugin-api/contract.mjs`，减少漏同步入口 |
| 插件只声明权限，遗漏对应的可选宿主能力 | 自动从文档、人设、模型、每日计划和音频权限推导能力要求 |
| 本机安装校验通过，但已运行的 DSH 仍为旧版 | 安装预览和目录显示实际缺失能力，已连接的旧宿主拒绝启用不兼容插件 |
| 未知权限只显示笼统错误 | 返回缺失权限/能力的具体名称及宿主升级步骤 |
| 宿主与 worker 来自不同源码版本 | 初始化握手核对契约，失败时报告 `PLUGIN_HOST_CONTRACT_MISMATCH` |
| `requiresAccount` 插件在未绑定账号时仍会初始化 | 初始化前检查账号绑定，未绑定时不运行入口代码 |
| `chats:null`（全部聊天）在目录接口中被显示为空数组 | 保留 null 语义，界面和保存逻辑不再误改范围 |
| 宿主文件变化未完全进入 DSH 加载版本 | 覆盖所有已声明的运行模块；发布检查拒绝遗漏的顶层或嵌套运行模块 |
| 源码包只允许旧记事本 ZIP | 统一第一方包清单，加入语音插件，对源码、ZIP 身份和 SHA256 同时核对 |
| 开发源码更新，但公开源码或安装模板漏文件 | 安装器构建前后及源码构建前自动检查宿主完整性，支持 `--compare` 比较两版 SDK |

## 维护命令

```powershell
npm run plugin:pack
npm run plugin:check
npm run test:plugin-contract
npm run test:plugins-v2
npm run source:build
```

`plugin:pack` 只重新生成经过明确列举的第一方 ZIP，不安装。`source:build` 先运行宿主和隐私检查，再生成源码包与来源哈希。安装器也会校验实际打包目录，不能仅凭开发目录的检查结果继续构建。

开发版与公开版可能保留各自的聊天功能实现；`plugin-host-check.mjs --compare <另一工作区>` 严格比较共享插件 SDK，同时独立检查各版本的媒体接入和发布文件，不覆盖无关差异。

## 2026-10-27 语音解码与 HTTP 协议修复

安装版 Python 3.13 没有适用的 pilk 预编译包，之前只提供可选依赖导致 WAV 上传在到达识别接口前失败。宿主现在随包提供固定 silk-wasm 3.7.1，保留许可、来源和逐文件哈希；能力检测实际运行合成编解码，发布检查要求包含完整载荷并核对哈希。无需 pip、本地识别模型或 GPU。

语音插件 1.1.1 标记实时协议模型，不将它们自动选为 HTTP 候选；聊天补全地址使用 multipart 时给出请求格式提示。所有 API 地址、密钥、模型和模板仍由安装者配置。

本次新增及相关 35 项 Node 测试、7 项 Python 语音权限测试通过，包括安装版 Python 3.13 与内置 Node/WASM 的实际转换。现场仅将已授权语音准备为本地 WAV，并用合成短句单独验证现有 API；没有重新投递历史语音或主动发送微信消息。实际新语音到模型回复的最终验收仍需用户发送新消息。

## 2026-10-28 语音协议重构

现场日志证实语音已经接收，失败来自识别接口 HTTP 403；内置解码正常。新版参考 DSH 的协议/基础地址/模型分离结构，统一模型发现和实际请求的路由、鉴权与结果解析，支持模型别名映射；目录不再跨服务根路径猜测，标准请求拒绝空模型，旧 JSON 和自定义字段映射保留。

新增真实语音状态记录（受设置代次约束，仅保存受控元数据）、收到但转写失败的占位，以及有界的并发等待。近期真实失败会覆盖更早的合成成功提示。已通过合成数据与模拟服务的协议、队列、诊断、授权和兼容性测试；现场同服务读取到 182 个模型，内置合成短句转写成功。当前运行配置已备份修正。用户选择自行重发语音验收，没有代为上传旧语音或主动触发微信回复。
