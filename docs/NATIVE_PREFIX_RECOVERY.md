# 人格前缀校验与上下文修复

## 适用范围

适用于聊天模式、近期窗口上下文中出现的 `HISTORY_NATIVE_PREFIX_MISSING`。DSH 可能保留旧的首条 system 消息，再追加新版系统提示词；程序按最后一条非空 system 快照验证当前人格与规则，不再把旧首条当作唯一依据。

用户、助手、工具消息或思考内容不能代替 system 前缀。实际缺失或最新 system 使用了其他人格时，仍会在调用模型前拒绝本轮，保留原始历史，不会通过删除校验继续运行。

## 自动恢复

确认缺失后，下一条新消息会重新绑定一次当前聊天的系统前缀。相同前缀持续失败时不会无限重复注册；只有真实模型请求通过校验，状态才变为“已验证”。

恢复沿用当前会话 ID、工作区、人格和能力权限。不重复投递之前已经进入 DSH 的失败批次，不重跑已执行的工具。原生消息原文仍保存在历史中。

## 从页面修复

1. 打开“聊天”，选择对应好友或群聊，进入“历史与用量”。
2. 点击“修复上下文”，核对确认说明后执行。正在回复时按钮不可用；服务端也会检查忙碌状态。
3. 页面显示“已重新绑定，等待下一条新消息验证”。发送一条新消息，成功通过前缀校验后完成验证。

此操作重新绑定人格前缀、刷新模型可见窗口，不创建新的会话，不删除原始消息，不调用模型生成摘要。与“压缩上下文”是两种操作；不使用原生前缀的会话不显示此按钮。

修复前的配置检查点保存在当前工作区的 `state/dsh-session-recovery/` 下，以 `.prefix.json` 结尾。已有检查点和 DSH 原始历史不会被覆盖。页面只显示当前聊天状态，不展示人格正文或请求中的聊天内容。

会话 ID 或微信账号已经变化时，操作会停止并提示刷新；不需要手工修改 `generation`、计算 session ID 或删除 DSH 历史文件。

## 应用源码修复

开发版和公开版源码已包含此逻辑。已安装版本需要更新对应程序文件后，完整退出并重开 DSH，再重启 WeChatAgent 后台、刷新页面，以加载新版插件和控制台。仅重新打开旧安装包不会获得源码中的修复。
